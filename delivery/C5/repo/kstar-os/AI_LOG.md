# AI 使用日志（本仓库开发过程）

> 记录"让 AI 做什么 → 它给了什么 → 我改了什么 → 为什么"。
> 被否掉的建议保留，因为否掉的理由比采纳的更有信息量。

## 1. 起点

目标不是"做一个笔记工具"，而是解决三个具体问题：

1. 下次遇到同类任务，先看到上次的坑；
2. 同一套步骤做第三遍时，变成可调用技能；
3. 做完之后，实际结果与事前预期的差值可计算。

**prompt 要点**：
> 「不要先写代码。先用三句话说明：如果只做一件事，能让这个系统区别于普通笔记，应该是什么？」

**AI 回答**：强制记录 R̂ 并计算 ΔR。
**采纳**：成为 `episode` 命令的必填参数；没有 R̂ 不允许写入 L2。

---

## 2. 存储选型：Markdown vs SQLite

**AI 建议**：SQLite + FTS5，理由是检索快、支持结构化查询。

**我的判断**：当前规模（5 条经验、6 个技能）用不上；而"十年后还能打开"比"快 20ms"重要。
**折中**：JSON 索引 + 线性扫描，`recall` 超过 300ms 再换 FTS。这个触发条件写进了架构文档，避免以后凭感觉优化。

---

## 3. CLI 设计

**prompt 要点**：
> 「设计一个零依赖 CLI，覆盖 capture / episode / skill-new / skill-use / skill-iter / recall / plan / reflect / status / export-html。每个命令只做一件事，输出要能直接贴进交付文档。」

**结果**：10 个命令，约 380 行，标准库 `argparse`。

**我改的地方**：
- 给 `episode` 加 `--expected/--actual` 必填，防止"先做后编预期"。
- 给 `reflect` 加 `--write`，避免把复盘只打在屏幕上、关掉就没了。
- `export-html` 不用任何 CDN，保证离线可开。

## 4. 真实 bug（3 个）

### bug 1：拼错技能名会创建幽灵技能

`skill-use submisson-audit`（少一个 i）不会报错，而是在 `L3_skills/submisson-audit/` 下静默创建 `usage.json`。
**根因**：`load_json(default)` 对不存在的路径返回默认值，`save_json` 又会 `mkdir(parents=True)`。
**修复**：新增 `_require_skill()`，检查 `SKILL.md` 是否存在，不存在直接退出码 2。
**测试**：`test_skill_use_rejects_unknown_skill`。

### bug 2：仪表盘挑战列顺序错

按 `(len(c), c)` 排序得到 `C1,C2,C3,C4,C2A...`，因为单字符比带后缀短。
**根因**：排序键选错，不是数据错。
**修复**：`re.match(r"C(\d+)([A-Z]?)")` → `(2,''),(2,'A'),(2,'G')`。
**发现方式**：看真实截图，不是看代码。

### bug 3：扫描器遍历全工作区超时

`rglob("*")` 把 227 文件的官方仓库、394MB 安装包都扫了，60 秒超时。
**修复**：`os.walk` + `SKIP` 集合，2 秒内完成。
**没有采用**："把超时调到 300 秒"——那只是让错误更晚暴露。

## 5. 测试

9 个用例，全部通过：

```bash
python3 -m unittest discover -s tests -v
# Ran 9 tests in 5.2s — OK
```

设计取舍：
- 每个用例把仓库复制到临时目录，避免污染真实记忆；
- 只测可观察行为（文件内容、退出码、输出关键词），不测内部函数；
- 不 mock 时间/文件系统，直接跑真实 CLI——这个项目的复杂度还没到需要 mock 的程度。

## 6. 被否掉的建议

| 建议 | 否掉理由 |
|---|---|
| 用 SQLite 存记忆 | 当前规模不需要；Markdown 的可读性与可迁移性更重要 |
| 用向量检索 | 5 条数据、零依赖约束；关键词 + 多写法足够 |
| 自动生成 R̂（让模型估） | 失去事前承诺的意义；校准必须由人写 |
| 在 L1 上支持编辑 | 会破坏归因，宁可保留噪声 |
| 用 Web 框架做界面 | 增加部署成本；先 CLI，界面用单文件 HTML |
| 把技能写成 JSON 配置 | Markdown 更适合"给人看 + 给 agent 读"的双重用途 |
