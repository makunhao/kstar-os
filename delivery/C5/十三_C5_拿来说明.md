## 二、仓库工程层面的拿来

| 来源 | 链接 | 拿了什么 | 改了什么 |
|---|---|---|---|
| Keep a Changelog | https://keepachangelog.com | CHANGELOG 结构 | 只保留 Added/Changed/Fixed |
| Semantic Versioning | https://semver.org | 版本号规则 | 0.x 阶段，破坏性改动升 minor |
| GitHub Issue Forms | GitHub 文档 | YAML 表单式 issue 模板 | 增加"边界检查"勾选项，直接对应项目约束 |
| Python `unittest` | 标准库文档 | 测试组织 | 每个用例复制仓库到临时目录，避免污染真实数据 |
| GitHub Actions 矩阵构建 | 官方示例 | 多版本 Python 测试 | 增加"禁止第三方 import"检查 |

## 三、明确没拿的

| 没拿 | 原因 |
|---|---|
| 现成的 Python 项目模板（cookiecutter 等） | 会带进一堆用不到的结构（setup.py、tox、docs 构建） |
| pre-commit 框架 | 一个 9 测试的项目不需要额外工具链 |
| 代码覆盖率服务 | 无第三方依赖的约束优先；覆盖率可本地跑 |
| 别人的 README 文案 | 容易写成"功能列表"，而不是"解决什么问题" |
