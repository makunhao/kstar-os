## 二、技术选择与理由

| 选择 | 拿了什么 | 为什么不选另一个 |
|---|---|---|
| Markdown + JSON | 通用、可读、可进 git | 不用 SQLite：当前数据量小，可迁移性优先 |
| Python 标准库 | `argparse` / `pathlib` / `json` | 不引入 click/rich：零依赖能在任何机器跑 |
| 单文件 HTML | 内联 CSS/JS | 不用 Tailwind CDN：离线打不开 |
| JSON 索引 | `episodes.json` 显式索引 | 不用目录扫描：排序与统计更稳定 |

## 三、明确没拿的

| 没拿 | 原因 |
|---|---|
| LangChain / LlamaIndex | 本系统不需要 agent 编排框架；Markdown + CLI 足够 |
| 向量数据库 | 7 条数据；引入后增加部署与迁移成本 |
| 云同步 / 账号 | 隐私与可迁移性优先；用 git 备份 |
| 商业笔记软件的模板 | 会绑定特定应用；数据必须属于自己 |
| 任何"AI 自动总结"功能 | 摘要会制造"看起来有用"的内容，且无法校准 |

## 六、如果只记一条

> 拿来的应该是**约束**，不是功能。
> "L1 只追加""没有 ΔR 不算经验""技能必须有使用记录"——这三条约束决定了系统会不会退化成笔记软件；
> 功能可以慢慢加，约束一旦丢了就找不回来。
