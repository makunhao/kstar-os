# C10 AI 日志：构建第二大脑

> 完整工程日志在 `agent-os` 仓库的 `AI_LOG.md`；这里记录设计决策、真实 bug 与被否掉的方案。

## Round 0 · 从"三个问题"开始

**prompt 要点**：
> 「不要先给架构。先回答：一个个人知识系统，如果只能解决一个问题，应该解决什么？给出三个候选，并说明哪个最容易失败。」

**它给的三个**：① 检索更快；② 自动总结；③ 校准预期。
**选择③**：因为①已有成熟工具，②会产生"看起来有用"的摘要；③几乎没有工具认真做。

**这一步决定了后面的所有设计**：`episode` 命令要求 R̂ 与 R，`reflect` 聚合 ΔR。

---

## Round 1 · 四层记忆怎么分

**prompt 要点**：
> 「PARA 是四层、Zettelkasten 是网络。现在要设计四层记忆（L1 原始 / L2 经验 / L3 技能 / L4 身份），给出每层的写入规则与晋升条件。」

**产出**：
- L1 只追加，不改写；
- L2 必须有 ΔR；
- L3 从 ≥3 次同类经验或 ≥2 次复用中抽象；
- L4 只写原则与工具边界。

**我的修改**：给 L3 增加 `usage.json` 与 `iterations.md`，否则技能库会变成"文档库"。

## Round 2 · CLI

**prompt 要点**：
> 「设计 10 个命令，每个只做一件事，输出能直接贴进交付文档。零第三方依赖。」

**产出**：`kstar.py` 约 380 行。
**我改的**：
- `episode` 的 `--expected/--actual` 设为必填（防止事后编预期）。
- `reflect --write` 落盘（避免复盘只打在屏幕上）。
- `export-html` 不用 CDN（离线可开）。

## Round 3 · 真实 bug 1：幽灵技能

**现象**：`skill-use submisson-audit`（少一个 i）不报错，创建了一个空技能目录并写入 `usage.json`。

**根因**：`load_json` 对不存在的文件返回默认值，`save_json` 又自动 `mkdir(parents=True)`。两个"宽容"设计叠加。

**修复**：`_require_skill()` 检查 `SKILL.md`，不存在退出码 2。
**测试**：`test_skill_use_rejects_unknown_skill`（先红后绿）。

**AI 建议过**：「自动纠正拼写，找最接近的技能名。」
**否掉**：模糊匹配会在真正想新建技能时误判；明确报错更安全。

---

## Round 4 · 真实 bug 2：排序

**现象**：仪表盘挑战列 `C1,C2,C3,C4,C2A,C2G…`。
**根因**：`(len(c), c)` 排序，单字符优先。
**修复**：按 `C(\d+)([A-Z]?)` 自然排序。
**发现方式**：截图，不是代码审阅。

---

## Round 5 · 真实 bug 3：扫描器超时

`rglob("*")` 扫全工作区（含 227 文件的官方仓库、394MB 安装包），60 秒超时。
**修复**：`os.walk` + `SKIP` 集合，2 秒内完成。
**否掉**：「把超时调到 300 秒」。

---

## Round 6 · 导入历史经验

**做法**：写 `import_legacy.py`，把 2026-10-02/04 的 5 条真实经历转成 L2，保留 `source` 字段。
**关键**：ΔR 标注为"事后估计"，不伪装成实时记录。
**结果**：平均 |ΔR| 0.319，4/5 为负。

**AI 建议过**：「让模型给这 5 条重新打分，使分布更好看。」
**否掉**：改历史数据等于伪造校准结果。

## 被否掉的方案

| 方案 | 理由 |
|---|---|
| SQLite + FTS5 | 当前规模不需要；Markdown 的可迁移性更重要 |
| 向量检索 | 7 条数据，零依赖优先 |
| 自动生成 R̂ | 失去事前承诺，校准无意义 |
| 自动改写 L1 | 破坏归因 |
| Web 框架做界面 | 部署成本高；先 CLI + 单文件 HTML |
| 技能写成 JSON | Markdown 同时适合人读与 agent 读 |
| 拼写自动纠正 | 会误判"新建技能"的意图 |

## 当前边界

- 建立仅 1 天，"连续两周使用"未满足；已导入历史经验做冷启动，但不冒充长期使用。
- L1→L2 半自动、同义词检索、技能淘汰提醒尚未实现。
