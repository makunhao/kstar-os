# C10 系统级 AAR：KSTAR OS

> 这不是"这个作业做得怎么样"，而是"这套系统本身哪里设计对了、哪里错了"。

## 0. 当前规模（2026-11-16）

| 项 | 值 |
|---|---|
| L2 经验 | 7 条（5 条历史导入 + 2 条本次） |
| L3 技能 | 6 个，全部至少调用 1 次 |
| 技能调用 | 7 次 |
| 技能迭代 | 1 次（dashboard-build v0.1→v0.2） |
| 平均 \|ΔR\| | 0.319（历史导入样本偏大，说明当时预期普遍过乐观） |
| 运行日志 | 12 条（`logs/agent_runs.jsonl`） |
| 测试 | 9/9 通过 |

## 1. 什么设计是对的

### 1.1 强制 R̂ 与 ΔR

没有 R̂ 就不允许写 L2。这条规则让 7 条经验里每一条都能回答"我原本以为会怎样"。
导入的 5 条历史经验里，4 条 ΔR 为负，平均 −0.27——**这个数字本身就是系统最大的产出**。

### 1.2 Markdown + JSON，而不是数据库

7 条经验、6 个技能，用 `grep` 就能查；数据能进 git、能直接读、能十年后打开。
代价是线性检索，但目前 `recall` <50ms，远未到需要优化的程度。

### 1.3 技能必须有 usage.json

6 个技能里，`dashboard-build` 的第一次调用就暴露了排序 bug，并触发了 v0.2。
如果技能只是"写好的文档"，这个 bug 不会被记录，也不会被修。

### 1.4 脚本型技能与流程型技能分开

`submission-audit` 等 5 个是脚本型：判断标准固定、可回归。
`content-outline` 是流程型：只给骨架，不替人写。
**把写作变成填空，会得到一堆正确但没用的文章。**

## 2. 什么设计是错的

### 2.1 "技能创建"太容易，导致幽灵技能

`skill-use submisson-audit`（拼错）不会报错，会创建一个空技能目录。
这是"贴心默认值 + 自动建目录"叠加的后果。
已修：先检查 `SKILL.md`，不存在退出码 2，并有测试覆盖。
**教训：写入类命令必须默认严格，不能默认宽容。**

### 2.2 L1→L2 仍是手动

系统能 `capture`，但不能把 L1 自动整理成候选经验。
7 条经验里 5 条是手动导入的，说明"记录"这一步的摩擦仍然高。
下一步应该做"从 git log / 日志生成候选 episode"，而不是要求人主动写。

### 2.3 检索只支持字面匹配

"交付" 搜不到 "提交"，"渲染" 搜不到 "排版"。
当前用"多写几个说法"绕过，但这不是长久方案。

### 2.4 两周使用要求未满足

系统建立于 2026-11-16，当天就投入了 C5/C6/C6A/C7 的实际工作，但**只有一天的真实使用**。
导入的历史经验是"用这套结构整理旧经历"，不等于"用了两个月"。
这一条如实写进边界，不用"已导入历史"冒充"长期使用"。

## 3. 最意外的发现

**ΔR 为负的 4 条经验，全部对应真实返工**：
C3 抽样误判、C4B 代码块返工、C4C 特征值符号错、C2G 预测被推翻。
而 ΔR 为正的那条（C4A 黄金集），是唯一一条"验证集来自真实数据"的经历。

这暗示一个规律：**当你用真实数据验证时，结果往往比预期好；当你凭直觉推进时，结果往往比预期差。**
样本只有 5 条，不能当结论，但值得作为下一次的假设。

## 4. 如果重新来一次

- **保留**：四层记忆、强制 ΔR、脚本型技能与 usage.json、零依赖。
- **改变**：第一周就做"从既有日志批量导入"的工具，而不是等到需要时手写。
- **砍掉**：`export-html` 的第一版复杂样式；先出纯表格，再谈好看。
- **提前**：写测试之前先写一个错误路径清单（幽灵技能就是这样漏掉的）。

## 5. 下一步进化

**短期（1 个月）**
1. L1→L2 半自动：从 `agent_runs.jsonl` 与 git log 生成候选 episode。
2. 检索加同义词表（交付/提交、渲染/排版、自检/校验）。
3. 技能淘汰提醒：连续 4 周零调用 → deprecated。

**长期（1 年）**
1. 多设备同步（git 远程 + 冲突处理）。
2. 技能组合（macro-skill）：`submission-audit + dashboard-build` 合并为"交付验收"。
3. 把 ΔR 做成可视化面板，按项目/技能看偏差趋势。

## 6. 一句话

> 这个系统今天最大的价值，不是它有多少技能，而是它让我看见：
> **我在 5 件事上平均高估了自己 27%。**
> 技能可以慢慢加，这个认知必须先有。
