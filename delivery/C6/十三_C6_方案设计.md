# C6 方案设计：KSTAR 助手

## 一、产品定义

**一句话**：输入任务与情境，先检索你的经验，再生成一份带 R̂ 的 KSTAR 计划；做完回填 R，差值进入经验库。

**不做**：待办清单、项目管理、社交、云同步、复杂图表。
**理由**：每加一个功能，首屏就多一层；C6 的硬指标是"30 秒内看懂"。

## 二、用户流程（3 步）

```
写任务 + 情境 + R̂
   ↓ 点「检索相似经验」（本机）
看到 3–6 条相关经验/技能
   ↓ 点「生成 KSTAR 计划」
得到 K/S/T/Â/R̂ 五段 → 复制 / 下载
```

## 三、AI 集成方案

| 方案 | 做法 | 问题 | 选择 |
|---|---|---|---|
| A 后端代理 | 服务端存 Key | 需要服务器，Pages 不支持 | ✗ |
| B 前端硬编码 | Key 写进 JS | 泄露 | ✗ |
| C 用户自带 Key | 页面输入，只存内存 | 首次多一步 | ✓ |

**调用点**：把「任务 + 情境 + 检索到的经验」拼成 prompt，调用 OpenAI 兼容 `/chat/completions`。

**无 Key 时**：模板模式，页面明确显示；按钮不假装可用。
**有 Key 时**：AI 模式，模型生成更具体的步骤与 R̂ 建议。

## 四、检索实现

- 纯前端：中文 2-gram + 英文词，按命中次数排序，取前 6。
- 数据内嵌：5 条经验 + 6 个技能元数据（来自 `kstar-os/memory/`）。
- 已知失效场景：同义词（"交付" vs "提交"）。文档里写明，不假装解决。

## 五、界面与技术

| 项 | 选择 | 理由 |
|---|---|---|
| 技术栈 | 单文件 HTML/CSS/JS | 零构建、离线可开、部署简单 |
| 布局 | 两栏（输入/计划），<900px 单栏 | 手机可用 |
| 颜色 | 暖白底 + 墨蓝强调 | 长文本阅读 |
| 存储 | 无（Key 只在内存） | 避免泄露 |
| 部署 | GitHub Pages（`/web`） | 免费、与仓库同源 |

## 六、与 C5/C10 的关系

- 源码 = `kstar-os/web/index.html`（C5 仓库的一部分）。
- 数据 = C10 的记忆文件（5 条经验、6 个技能）。
- 没有第二份代码；C6 是同一系统的"界面层"。

## 七、验收标准（对应挑战的五条"可用"）

| 要求 | 自检 |
|---|---|
| 30 秒知道干什么 | 首屏标题 + 一句说明 + 两个按钮 |
| 不需登录 | ✅ 无账号体系 |
| 核心流程走通 | 输入→检索→生成→复制，截图验证 |
| 手机可用 | 390×844 截图 |
| 加载 <5 秒 | 单文件 30KB 内，无外部请求 |
