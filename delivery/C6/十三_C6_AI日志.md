# C6 AI 日志：KSTAR 助手

## Round 0 · 产品定义（先写"不做什么"）

**prompt 要点**：
> 「C6 要求 AI 是核心功能、必须部署、30 秒内看懂。先不要写代码：列出这个产品必须砍掉的功能，并说明为什么砍掉比加上更能提高可用性。」

**输出**：砍掉登录、云同步、多人协作、复杂图表。
**采纳理由**：这些都是"看起来完整"的功能，但会让首屏变重、部署变复杂，并且与"个人第二大脑"的定位冲突。

**保留的最小闭环**：写任务 → 检索经验 → 生成计划 → 复制/下载。

---

## Round 1 · AI 集成方式（关键决策）

三个方案：

| 方案 | 做法 | 问题 |
|---|---|---|
| A | 后端代理，服务端存 Key | 需要服务器与密钥管理，GitHub Pages 做不到 |
| B | 前端硬编码 Key | 泄露，直接违反挑战的安全要求 |
| C | 用户自带 Key，只存内存 | 首次使用多一步；但零泄露、零后端 |

**选择 C**。页面上明确显示"模板模式 / AI 模式"，**没有 Key 时按钮不假装可用**。
挑战文档也明确允许"让用户自己输入 key"。

**AI 调用点**：把「任务 + 情境 + 检索到的经验」拼成 prompt，调用 OpenAI 兼容的 `/chat/completions`，返回 KSTAR 计划。

**它建议过**：「放一个'AI 生成'按钮，没 Key 时返回预设文本，看起来功能完整。」
**我否掉**：这就是挑战里点名的"假集成"。

## Round 2 · 检索实现（不用向量）

**prompt 要点**：
> 「在纯前端、零依赖、数据只有 5 条经验 6 个技能的前提下，最合适的检索是什么？给出排序公式和它的失效场景。」

**结果**：中文 2-gram + 英文词的计数打分；按命中数降序，取前 6。
**失效场景**：同义表达（"交付" vs "提交"）会漏。已写进页面提示与 AAR。

**它建议过**：「引入 transformers.js 做 embedding。」
**我否掉**：模型文件几 MB 到几十 MB，首屏会超过 5 秒；5 条数据不值得。

## Round 3 · 界面

**prompt 要点**：
> 「两栏布局：左边输入，右边计划。要求手机 390px 宽时自动变单栏；不要用 Tailwind CDN（离线要能开）。」

**结果**：约 120 行 CSS，CSS 变量控制颜色，`@media(max-width:900px)` 切单栏。
**验收**：Playwright 1440×1000 与 390×844 两种宽度截图，确认无横向滚动。

## Round 4 · 真实 bug / 返工

| 问题 | 现象 | 处理 |
|---|---|---|
| 计划区高度不足 | `textarea` 默认高度只显示半页，R̂ 段被截断 | 设 `min-height:420px`，并保留滚动 |
| 检索命中为 0 时无反馈 | 用户以为按钮坏了 | 增加"没有命中，换个说法或先记进 L1" |
| 复制在非 HTTPS 下失败 | `navigator.clipboard` 需要安全上下文 | 加 `document.execCommand('copy')` 回退 |
| 移动端按钮换行拥挤 | 三个按钮挤在一行 | `flex-wrap:wrap` + 按钮间距 |

**发现方式**：全部来自真实截图与点击，不是代码审阅。

## 被否掉的建议

| 建议 | 理由 |
|---|---|
| 假 AI 按钮返回预设文本 | 挑战明确把"假集成"列为不算 |
| 前端硬编码 API Key | 泄露风险，且违反检查清单 |
| 引入 React/Vite | 单页 10KB 的产品不需要构建链 |
| 用向量检索 | 首屏体积与收益不匹配 |
| 加登录/云同步 | 与"个人工具"定位冲突，增加部署门槛 |
