# C6 拿来说明

## 一、产品层面

| 来源 | 链接 | 拿了什么 | 改了什么 |
|---|---|---|---|
| KSTAR 教学框架 | 课程材料 | K/S/T/Â/R̂ 五段结构 | 把 R̂ 做成页面上的必填输入，并把 ΔR 写成页面提示 |
| Obsidian 的"本地优先" | https://obsidian.md | 数据属于用户、离线可用 | 不做桌面端，改为单文件网页；数据内嵌为 JSON |
| Linear / Notion 的表单交互 | 产品观察 | 左输入右结果的兩栏结构、低饱和配色 | 简化为两栏 + 两个按钮，去掉导航与侧边栏 |
| Anthropic 的 API Key 安全建议 | https://docs.claude.com | 不把 Key 写进前端；让用户输入 | 改为"只存内存、刷新即清空"，并显示当前模式 |

## 二、技术层面

| 来源 | 拿了什么 | 改了什么 |
|---|---|---|
| OpenAI Chat Completions 协议 | `/chat/completions` 请求/响应结构 | 兼容任意 base URL；不绑定厂商 |
| MDN Clipboard API | `navigator.clipboard.writeText` | 增加 `execCommand` 回退以支持 `file://` |
| 自建 `dashboard-build` 的 CSS 变量体系 | 颜色与卡片样式 | 改为暖色纸感主题，适配长文本阅读 |
| 自建 `content-outline` 的结构 | 计划模板的段落顺序 | 把"证据"换成"K 检索结果" |

## 三、明确没拿的

| 没拿 | 原因 |
|---|---|
| Tailwind CDN | 离线打开会掉样式；挑战要求"任何人打开就能用" |
| React/Vite | 构建链对单页产品是负担 |
| 向量检索库 | 数据 5 条，首屏体积不划算 |
| 现成的 AI 聊天 UI 模板 | 会把产品变成"另一个聊天框"，偏离"计划生成器" |
| 后端服务 | GitHub Pages 不支持；引入后部署门槛变高 |

## 四、数据来源

- 经验与技能元数据来自 `kstar-os/memory/`（5 条真实经验、6 个技能）。
- 演示输入（"把 C6A 仪表盘改成能扫描任意提交目录"）来自本次真实任务，不是编的样例。

## 五、合规

- 页面不收集任何用户数据；没有埋点、没有第三方请求。
- 只有用户主动填写 Key 并点击生成时，才会向用户填写的接口地址发送请求。
- 未使用任何需要登录的第三方服务作为核心功能。
